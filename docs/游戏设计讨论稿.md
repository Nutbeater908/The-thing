# The Thing · 游戏设计讨论稿

> 整理日期：2026-11-10
> 状态：阶段性讨论记录，不是全部定稿的制作规格。
> 用途：归纳已经讨论出的方向，保留未决问题；本轮不补充新规则或具体数值。
> 历史文档：`设计大纲.md`、`设计大纲.docx` 保留原样，其中俯视视角、7×5 网格及部分接口描述已过时，不作为当前规则依据。

## 一、阅读约定

- **已确认方向**：用户已明确认可的设计意图，不等于已完成开发。
- **前期设想**：保留供以后使用，允许调整或放弃。
- **待讨论**：尚未确定，不据此直接实施。
- **原型现状**：只说明现在可以运行什么，不反向规定最终设计。

## 二、游戏定位与核心体验

### 已确认方向

- 横版 2D 生物拼装动作肉鸽。
- 原有玩家身份是脑寄生虫，通过拼装器官构成宿主生物；具体剧情与逃亡背景如何衔接，留待以后讨论。
- 不限人形，重点是组合身体、改变能力，并在战斗与环境中体验这些改变。
- 拼装真实影响能力与战斗，但**不要求肢体真实承重，也不要求身体通过物理模拟自行站稳**。
- 优先保证操作流畅、反馈清晰与完整可玩，不以复杂物理模拟本身为目标。

### 美学基础

沿用血腥、怪诞、缝合生物的方向。美术细节尚未全面定稿；当前使用占位表现验证玩法。

## 三、关卡推进与拼装循环

### 已确认方向

采用沿路线前进、沿途休整的结构，参考《死亡细胞》的关间休息节奏；**不要求每过一关都返回初始基地**。

```text
初始拼装
  → 关卡内移动、战斗、搜刮
  → 沿途休息处完整拼装
  → 继续下一关
  → ……
```

关卡途中还有一个补充循环：

```text
获得新器官
  → 当前区域安全、已无敌人
  → 受限的简易拼装／试装
  → 尽快在后续战斗中体验新能力
```

### 两种拼装场合

| 场合 | 设计定位 | 尚未确定的部分 |
|---|---|---|
| 沿途休息处 | 提供完整拼装机会，支持整理和改变身体 | 每小关末还是每大关末；是否提供治疗、购买等服务 |
| 途中安全区域 | 提供受限制的简易拼装，优先让新器官尽快可用 | 如何划分安全区域、可改装范围、操作限制与费用 |

- 完整拼装机会的频率尚未定稿：每小关结束或每大关结束均在考虑中。
- 简易拼装以“捡到新器官马上试”为优先目的，而非单纯维修工具。
- 临时修补也应纳入考虑，避免玩家长时间被损伤拖累；具体机制待定。
- 本次尚未决定完整拼装与简易拼装各自允许哪些具体操作。

## 四、拼装如何影响行动

### 1. 腿与动作模组——已确认方向

腿的数量与组合不只是线性增加属性，而是先改变动作模组，再影响基础表现：

```text
腿的组合 → 动作模组 → 速度、跳跃、稳定性等表现
```

- 一条腿与两条腿不仅有数量差异，更重要的是动作类型／模组不同。
- 独腿蹦跳、双腿行走、多腿波浪步态已有实验原型；这些实验不能代表所有布局都已适配，也不意味着最终动作已全部定稿。
- 最终各模组的属性关系、触发条件及可支持布局待讨论。

### 2. 功能器官的位置与朝向——已确认方向

- 生物可以自由转向，因此器官装在前面或后面没有绝对、本质的优劣。
- 位置仍会影响玩家操作，以及玩家如何利用器官；不能据此把位置差异完全抹掉。
- 攻击发出位置、覆盖范围、朝向与具体操作之间的规则尚待确定。
- 不预设“背面的器官直接失效”等尚未讨论的规则。

### 3. 身体形态差异——前期机制设想

- 不同身体形态应有实际差异，而不只是视觉变化。
- 考虑引入**血压、氧含量**等机制表达差异，例如高耸的身体需要更高血压。
- 是否采用、分别管理什么、如何反馈与计算，均未定稿；目前不增加实现任务。
- 不将血压、氧供、供血能力混为已经确立的一组规则。

### 4. 体型与碰撞——待讨论

不同拼装外形如何对应碰撞体积、通行能力和受击范围，尚未确定。固定胶囊运动原型只验证控制底座，不等于已解决任意外形碰撞。

## 五、约束与器官组合的取舍

### 已确认方向

- 先使用已有的空间、接口、连接与供血等限制，观察是否足以阻止无脑堆器官。
- **不为了预防未知问题提前增加一整套限制系统。** 如果实际玩法出现“器官越多永远越好”，再针对问题补充规则。
- 血压、氧含量是体型差异化的候选机制，不自动成为新增堆叠限制。

### 现有拼装基础

原型有异形网格器官、旋转、神经／血流／骨骼接点及拉线，提供控制链、血路与结构校验。数值与定义使用资源数据维护。

当前拼装盘为 9×7。网格尺寸与原型具体参数不等同于最终设计承诺；设计正文不复制容易过期的完整数值表。

## 六、战斗、损伤与临时修补

### 已确认的体验目标

- 游戏预期战斗较多，身体并非特别坚韧，损伤会较常见。
- 不希望玩家被迫长期带着难受的损伤继续闯关，即使途中有休息处，也需要考虑损伤的缓解方式。
- 途中简易拼装首先服务尝新，同时可以考虑身体受损后的临时修补。

### 尚未定稿

- 普通受伤、严重损伤与器官损毁分别怎样影响功能。
- 器官损毁后是否脱落，以及神经／血流断开是否导致连带失效。
- 多个攻击器官如何控制、朝向如何决定，以及是否需要闪避或远程能力。
- 修复消耗什么、在哪里能修、是否存在治疗服务，以及拆装如何处理 HP。
- 如何避免每场战斗后都必须反复维护身体的繁琐体验。

**说明：**此前提出的“轻伤只扣 HP”“通用资源修复”“拆装不回血”等均只是助手建议，未获明确确认，本稿不将其写成正式规则。

## 七、搜刮与即时正反馈

### 已确认方向

- 新器官应尽快带来可体验的变化。
- 获得器官后，可以在途中安全条件下尝试受限改装，而不必一直等到整局结束。
- 休息处仍保留全面拼装的作用，简易拼装不能与完整拼装毫无区别；具体边界留待讨论。

### 待讨论

- 器官掉落、购买与解锁的分工。
- 掉落是否携带损伤，器官稀缺程度与库存限制。
- 修复、出售、代币及背包如何形成取舍。
- 如何让新器官既能作为新玩法选择，而不总被迫用来弥补刚失去的能力。

## 八、背景、关卡与可选主题

> 本节是前期设想。剧情暂缓细化，不要求玩法为寓意让路。

### 表层背景与关卡草案

实验室里的生物逃出，关卡随着逃亡向外推进。

| 大关 | 场景设想 | 可选的主题对应 |
|---|---|---|
| 第一大关 | 实验室 | 学校／学生时代，主要矛盾是受到规则束缚 |
| 第二大关 | 城市 | 成年后的生存问题，选择与自由度提高 |
| 第三大关 | 尚未构思 | 不预先指定地点、主题或结局 |

### 可选的深层表达

影射一个人从小时候到成年，为适应外界环境而改变自己；与通过拼装改变生物形态相呼应。如果未来希望为游戏赋予更深意义，可以沿此方向发展，但它目前不是必须实现的叙事规格。

脑寄生虫、宿主与逃出实验室的生物之间的身份关系，以及人物动机、结局等，尚未讨论清楚。

## 九、当前原型与设计目标的区别

| 项目 | 当前情况 | 不代表什么 |
|---|---|---|
| 拼装与基础系统 | 已有放置旋转、拉线、存活校验、胃、经济、修复、方案与存档原型 | 所有玩法与数值已定稿 |
| 动作模组实验 | 已有独腿、双腿、多腿实验及受限拼装测试入口 | 任意拼装、任意腿数、任意地形均可用 |
| 连续坡道 | 双腿有已验证版本；真实四腿实验仍存在问题，暂停扩展 | 多腿复杂地形适配已完成 |
| 原生角色底座 | CharacterBody2D 已完成坡面、跳跃、击退对照，作为后续可玩方向 | 不同拼装外形已映射到原生碰撞 |
| 短关卡切片 | 固定身体移动、跳跃、攻击、受伤、死亡重试、搜刮、出口与回池；用户已实操确认正常 | 已使用玩家实际拼装；演示掉落已带入正式存档 |
| 沿途休息与简易拼装 | 本次确认的设计方向 | 已在关卡中实现 |

短关卡切片使用局内演示收获，不保存真实进度。现有返回孵化池的演示流程不是最终“每关回初始基地”的设计。

## 十、保留到后续讨论

不在本轮展开以下细节：

- 完整拼装的关间频率与简易拼装的具体限制。
- 身体形态、动作模组与碰撞／受击范围的映射。
- 战斗操作、器官损伤与修复规则。
- 一局长度、死亡损失、寄生虫逃脱与永久成长。
- 敌人差异、地形支持范围与关卡生成方式。
- 第一版内容数量、通关目标与明确不做的功能。

## 十一、制作原则

- 小、完整、可玩优先；先验证闭环，再增加内容和通用性。
- 引擎原生优先：场景组织固定节点，容器与Theme管理UI，资源维护参数，脚本负责必要逻辑。
- 已确认设计、候选设想和实际实现分别记录；实验通过不能替代完整玩法验证。
- 新美术使用前先预览确认；简单关卡操作交由用户手动测试，不做桌面输入注入。
- 本稿只整理讨论，不授权扩展功能、改存档、提交或上传仓库。
